Put a run/page index in every archive filename — a probe the same day overwrote page 0 with page 1 and produced a confident wrong number from half a menu.
- A PREDICTED *REGRESSION* IS A HYPOTHESIS TOO, AND A GUARD IS ONLY VERIFIED AGAINST THE BREAK YOU ACTUALLY TRIED (lesson 24). A spec claimed a chain-order change "will move dims"; measured, both orders scored identically, and the guard written to protect the order passed happily under the wrong one. Break EACH failure mode separately and watch the specific test go red.
- WHEN LIVE DISAGREES WITH OFFLINE, SUSPECT DIFFERENT SAMPLES BEFORE DIFFERENT CODE (lesson 27). Two confident mechanisms (input-fidelity mismatch, OCR drift) were refuted by a $0.004 probe; the real answer was that one side was a single draw. Order: is the baseline one sample or many? -> hold input constant and vary only the model output, then the reverse -> only then look for a code difference.
- SUSPECT OUR OWN POSTPROCESS BEFORE THE MODEL (lesson 21). Diff `<menu>.<tag>-r1.nopost.dump.json` (raw model output) against `.dump.json` (after postprocess) BEFORE theorising. In one session THREE recorded "model defects" were our own code deleting a correct extraction — including one that had a confident written diagnosis derived from the post-processed dump. The tell is a defect that looks like the model half-understanding something (it got one of two choices; it split a card; it kept the item but lost the variant). Models rarely fail that tidily; deterministic code does.
- A GATE MAY ONLY READ THE MOST UPSTREAM CACHED ARTIFACT — `*.raw.json` (lesson 20). Anything downstream (`.dump.json`, `.clean.dump.json`, `.actual.json`) was produced by the code as it stood when the probe ran, so scoring it makes the gate blind to the code it claims to measure.
