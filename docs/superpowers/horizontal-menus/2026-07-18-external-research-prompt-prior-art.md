I am building a mobile app that photographs restaurant menus and extracts structured items (name, price, weight/portion, section) using a vision LLM (GPT-4o) over overlapping 2×2 image tiles for dense menus, plus a deterministic post-extraction verification stage that checks every extracted item against printed-text evidence from a dedicated layout-OCR pass (Mistral OCR line blocks with pixel coordinates) — items whose name/price/weight contradict the print (with a verified duplicate present) or whose name is printed nowhere get dropped. This already works: zero false deletions across all our evaluations, and it kills most fabricated items.

The residual failure class I need prior art on is **cross-card field recombination / relational hallucination on dense multi-column menus**: the VLM emits items that borrow words and field values from NEIGHBORING printed cards, e.g.:
- A novel-name item minted from another card's description prose (menu prints a salad section with cards "Ensalada Boneless", "Aguacate Chicken", "Ensalada Pollotera", and a description elsewhere containing the words "ensalada de pollo a la plancha" → the model emits a nonexistent dish "Ensalada de Pollo (350gr) $159" with price/grams borrowed from adjacent cards).
- Same-name corrupted twins: real dish name + a neighbor's price or weight ("Boneless Jr $95" when the card prints $132).
- Word-mashup names combining two printed dishes ("Nuggets de Coliflor", "Chicken Bacon") that never exist as cards.

These items are dangerous because a user may try to order a dish that does not exist. Count-based accuracy metrics hide them.
