They are ORACLE files: never edit one without an explicit Santiago adjudication FROM THE PHOTO.
- SUSPECT OUR OWN POSTPROCESS BEFORE THE MODEL (lesson 21). Diff `<menu>.<tag>-r1.nopost.dump.json` (raw model output) against `.dump.json` (after postprocess) BEFORE theorising. In one session THREE recorded "model defects" were our own code deleting a correct extraction — including one that had a confident written diagnosis derived from the post-processed dump. The tell is a defect that looks like the model half-understanding something (it got one of two choices; it split a card; it kept the item but lost the variant). Models rarely fail that tidily; deterministic code does.
- A GATE MAY ONLY READ THE MOST UPSTREAM CACHED ARTIFACT — `*.raw.json` (lesson 20). Anything downstream (`.dump.json`, `.clean.dump.json`, `.actual.json`) was produced by the code as it stood when the probe ran, so scoring it makes the gate blind to the code it claims to measure. This already happened: `score-c-dumps.ts` scored `.dump.json` and three real fixes reported "no change". `scripts/gate-artifacts_test.ts` now fails any file that scores while touching a derived artifact — if you write a NEW gate (C3/C4), give it its own sensitivity guard too, because that test cannot force one.
- FOR ANY RULE THAT MERGES OR DELETES ITEMS, THE DELIVERABLE IS THE LIST OF THINGS IT REFUSES (lesson 22). Enumerate every candidate across all 9 menus and justify each refusal individually; then pin the refusals as named tests. Measured example: an unguarded shared-prefix fold fires 51 times and would merge real dishes on 7 of 9 menus; guarded it fires 6. Prefer a LAYOUT discriminator (is this printed on a line of its own? is it a `#` heading?) over a vocabulary one — layout carries no language assumption.
- IF A PROBE RESULT SURPRISES YOU, SUSPECT THE PROBE (lesson 23). Four planner probes produced confident wrong numbers in one session. Import the real helper rather than re-implementing it; if you must re-implement, copy it verbatim and say so; use a separator that cannot occur in the data (\x01, never a space); compare on TOKENS where the surrounding code tokenizes.
- A FIXTURE PIN HAS TWO ORACLES, NOT ONE (lesson 18): the scored extraction dumps AND the corrected draft. After ANY fixture or draft edit run `deno test --allow-read scripts/drafts_test.ts`. Eval 107 shipped required pins that scored the extractor perfectly and silently broke the guest-house draft for two days; that test now catches the class.
