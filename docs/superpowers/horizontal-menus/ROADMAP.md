## Architecture decisions (locked with user 2026-07-13)

- **ONE pipeline, no horizontal fork.** Orientation is an input property. No separate edge function/stage. Landscape behavior enters only as: (a) client-side upright rotation before upload (pipeline never sees rotated pixels); (b) aspect-ratio-parameterized dense-detection/tile-geometry inside the existing functions. A unit test pins *portrait input ⇒ byte-identical behavior to today* — vertical safety is proven by construction during iteration, not by burning gates.
- **Mode/aspect-scoped prompt changes only** (master-roadmap lesson from v6/v7): any P1 sentence added for landscape evidence must be scoped to where it was measured, never global, unless probe evidence justifies global.

## External research review (eval 070, $0 — 2026-07-17)

Santiago commissioned an external LLM deep-research report on dense horizontal-menu extraction (delivered 2026-07-15; archived here as `2026-07-15-external-research-dense-menus.md` — read it in full before designing Phase-1 probes). Planner assessment and what it changes:

- **The failure class is known and open.** Cross-card field recombination = DoorDash's "item↔attribute linkage" failure / relational VLM hallucination, caused by tile-based image encoding fragmenting dense regions — an architectural property, not a prompt defect. No published system guarantees zero recombination; production systems manage it with layout-first decomposition + spatial grounding/provenance.
- **Independent convergence:** the report's cheapest decisive experiment is exactly eval 069's recommended nested tile-3 probe, derived without ledger access. Its "count-tolerance masking" warning is our eval-067 proof; its "never auto-delete, flag instead" safety rule is our keep-bias discipline; its verdict that semantic plausibility cannot establish distinctness validates rejecting verifier v1–v3/batched/paired (evals 063–069) as correct process-of-elimination, not churn.
- **The one new mechanism: spatial co-location against a dedicated layout parser's boxes.** Require a candidate's name+price+grams to co-locate inside ONE region box from a real OCR/layout pass (VLM self-reported boxes are unreliable on dense small text). This operates on the actual root-cause variable — spatial card ownership — where every prior verifier operated on semantics.
- **Also adopted:** pixel stitching of repeated menu text is a documented duplicate generator → any future guided-capture pilot must be region-based with structured-data-level merge; GPT-4o is a legacy model with weak grounding → the bake-off must include layout-first candidates (Mistral OCR + LLM grouping, Gemini 3.x, PaddleOCR-VL), not only pure-VLM swaps.
- **Caveats:** the report's vendor pricing/benchmarks/launch dates are unverified secondary claims — re-verify official pricing at Eval-071 spec time before budgeting; the architectural argument stands on our own ledger evidence regardless.
